# Блок 1. Автоматизация кабинета Ozon через AdsPower Local API

## 1. Архитектура и логика работы скрипта

Главное решение во всей задаче: браузер запускает AdsPower, а не мой код. Отпечаток,
прокси и куки кабинета живут в профиле, поэтому playwright.chromium.launch() здесь не
подходит — он поднял бы чистый Chromium, то есть ровно без того, ради чего антидетект
и нужен. Я запускаю профиль через API и подключаюсь к уже живому процессу.

Запуск профиля по ID — это HTTP-запрос к локальному серверу, который поднимает само
приложение AdsPower (по умолчанию порт 50325). Я обращаюсь к эндпоинту
GET /api/v1/browser/start и передаю user_id — идентификатор профиля из интерфейса;
если его нет под рукой, весь список отдаёт эндпоинт /api/v1/user/list. Вместе с user_id
передаю open_tabs=0 и ip_tab=0, чтобы AdsPower не открывал стартовые вкладки и вкладку
проверки IP: они потом мешают выбрать рабочую страницу. Ключ доступа уходит заголовком
Authorization: Bearer — query-параметр api_key, описанный в распространённой
документации, версия 8.x отвергает с ответом Require api-key.

По этому запросу AdsPower запускает Chromium с отпечатком, прокси и куками профиля, а
возвращает точки подключения к браузеру: путь к webdriver для Selenium, debug_port и
готовый ws-адрес — порт Chrome DevTools Protocol, к которому подключаются Playwright и
Puppeteer. Проверяю также код ответа внутри тела, потому что ошибки приходят со
статусом 200, из-за чего отказ легко упустить. И ещё в клиенте настроен троттлинг: API
принимает не чаще одного запроса в секунду, а при превышении отвечает code=-1,
Too many request на случайном вызове, и связать это с настоящей причиной трудно.

Закрывается профиль симметрично, запросом GET /api/v1/browser/stop с тем же user_id, и
этот вызов у меня всегда стоит в finally: без него брошенные профили остаются живыми
процессами Chromium и через десяток прогонов кладут машину.

Прокси подключается в профиле AdsPower или при помощи эндпоинта POST /api/v1/user/update,
куда передаётся id профиля и user_proxy_config с типом, хостом, портом и доступами.
Держать прокси в профиле, а не на уровне машины, важно: так отпечаток и IP связаны в
одной сущности и разным кабинетам достаются разные адреса, тогда как системный VPN дал
бы всем профилям один выход. Сразу после запуска я проверяю, с какого адреса профиль
реально ходит, — запрашиваю сервис вроде ipify из самой страницы, а не с машины. Если
адрес не определился, работу не начинаю: когда прокси отваливается, AdsPower молча
выпускает трафик с домашнего IP, и кабинет улетает в бан. У мобильных прокси есть
ссылка принудительной смены IP из личного кабинета провайдера, это обычный GET-запрос;
дёргаю её только при подозрении на блокировку, потому что у операторов стоит
ограничение на частоту ротации, обычно не чаще раза в две минуты.

Целевое действие выполняется через Playwright: он подключается к браузеру по ws-адресу
методом connect_over_cdp. Беру существующий контекст профиля, а не новый, иначе получу
чистый профиль без авторизации в кабинете, и выбираю рабочую вкладку, пропуская
служебную вкладку DevTools, которую AdsPower открывает первой.

Порядок одинаков для любого действия: переход с ожиданием domcontentloaded, проверка,
что показали кабинет, а не страницу блокировки, и ожидание ключевого селектора.
Если действие — клик, дожидаюсь видимого элемента, кликаю и проверяю результат:
появился нужный селектор, сменился URL или всплыло уведомление, иначе скрипт
отрапортует об успехе на промахнувшемся клике. Если действие — сбор данных, обхожу
строки списка и читаю ячейки по data-атрибутам, а не по позициям колонок: вёрстка
меняется часто, и nth-child(3) ломается первым; пустая ячейка не роняет разбор строки.
При постраничном выводе перехожу на следующую страницу, пока кнопка не исчезнет. На
выход сценарий отдаёт готовый список объектов, а не разметку.

## 2. Обработка ошибок

Реакция зависит от уровня: единый try/except с ретраем как раз и приводит к банам
вместо данных — обрыв связи и капчу нельзя повторять одинаково.

Если элемент не прогрузился, жду ключевой селектор с таймаутом, не дождался —
перезагружаю страницу и повторяю, до трёх раз, с растущей паузой и джиттером; ровные
интервалы сами по себе выглядят как автоматизация. Зависшая страница — тот же случай,
диагноз другой: DOM есть, контента нет. Попытки исчерпаны — скриншот и остановка с
ошибкой, в которой видно, какого селектора не дождались. Жду domcontentloaded, а не
networkidle: кабинет держит вебсокеты, сеть не затихает никогда.

Капчу не ретраю в лоб: повторы с того же IP превращают проверку в устойчивый блок.
Скриншот, закрыть профиль, ротация IP, пауза три минуты, одна повторная попытка — не
помогло, зову человека. Саму капчу не решаю: технически это гонка, которую не выиграть,
а по правилам площадки — нарушение. Проверяю блокировку до ожидания селектора, иначе
потрачу весь таймаут на странице капчи и получу ложный диагноз «элемент не найден».
Признаки ищу по URL, разметке и тексту: на живом кабинете Ozon отдал Antibot Challenge
Page, и сработала только текстовая проверка.

На транспорте проще: API не отвечает — три попытки с растущей паузой; логический отказ
с code не равным нулю не повторяю, ответ не изменится. Проверено на стенде:
несуществующий профиль даёт Profile does not exist за 0,8 секунды без ретраев, мёртвый
порт — три попытки за три секунды. Отдельно проверяю прокси: адрес профиля не
определился — работу не начинаю, иначе трафик уйдёт с домашнего IP.

Каждый исход возвращает свой код, чтобы по логам было видно, нас заблокировали или
сломалась вёрстка.

## 3. Код: запуск профиля и получение вебдрайвера с портом отладки

Это единственный пункт блока, который задание просит реализовать кодом. Ниже сокращённый
фрагмент, полная версия — в репозитории, где клиент покрыт девятью тестами на замоканном
HTTP: троттлинг, ретраи транспорта, отказ при code не равном нулю, ключ в заголовке и
закрытие профиля при исключении.

```python
class AdsPower:
    START = "/api/v1/browser/start"

    @retry(  # только транспорт: логический отказ повторять незачем
        retry=retry_if_exception_type(ApiDown),
        wait=wait_exponential(multiplier=1, min=1, max=15),
        stop=stop_after_attempt(3),
        reraise=True,
    )
    def _get(self, path, params=None):
        self._wait_turn()                      # не чаще 1 запроса в секунду
        # С версии 8.x ключ принимается только заголовком.
        headers = {"Authorization": f"Bearer {self.key}"} if self.key else {}
        try:
            response = self._http.get(f"{self.api_url}{path}", params=params or {},
                                      headers=headers, timeout=self.timeout)
            response.raise_for_status()
            payload = response.json()
        except (requests.RequestException, ValueError) as exc:
            raise ApiDown(f"Local API недоступен: {exc}. Проверьте, что AdsPower "
                          "запущен и Local API включён.") from exc

        # Отказы Local API приезжают с HTTP 200.
        if payload.get("code") != 0:
            raise ApiRejected(payload.get("code", -1), payload.get("msg", ""))
        return payload.get("data") or {}

    def start(self, user_id, *, headless=False) -> Endpoint:
        """Открыть профиль по ID и получить вебдрайвер с портом отладки."""
        data = self._get(self.START,
                         {"user_id": user_id, "headless": int(headless),
                          "open_tabs": 0, "ip_tab": 0})
        ws = data.get("ws") or {}
        if not ws.get("puppeteer"):
            raise NoDebugPort(f"профиль {user_id} запущен, но точки отладки нет")
        return Endpoint(user_id, ws["puppeteer"], ws.get("selenium", ""),
                        str(data.get("debug_port", "")), data.get("webdriver", ""))


@contextmanager
def launched(ads, user_id, **kwargs):
    """Открыть профиль и закрыть на выходе."""
    endpoint = ads.start(user_id, **kwargs)
    try:
        yield endpoint
    finally:
        ads.stop(user_id)
```
